The Run Command feature uses the Azure VM Guest Agent to execute PowerShell scripts remotely within a Windows VM. Scripts run as NT AUTHORITY\SYSTEM — no RDP or open inbound ports required. This makes it the primary tool for diagnosing and remediating VMs that are inaccessible via RDP.

Scripts fall into two categories:

📌 Official Action Run Commands Published on Microsoft Learn with a named CommandId. Invocable directly via Portal, PowerShell Invoke-AzVMRunCommand, or CLI az vm run-command invoke. Source lives in the azure-support-scripts repo.
📦 GitHub-Only / Custom Scripts Diagnostic scripts hosted in the same GitHub repo but NOT registered as named CommandIds on the platform. Must be run by pasting contents into RunPowerShellScript (custom script slot) via Portal or by providing the -ScriptPath parameter.
💡 Tip for Support Cases: Always start with the appropriate named CommandId (e.g., RDPSettings, IMDSCertCheck) before escalating. For issues not covered by a named command, use RunPowerShellScript with the relevant GitHub script content.

⚙️How It Works

Execution Flow

  1. Portal/API call sends the command to Azure Fabric via ARM.
  2. The Azure Guest Agent on the VM receives the script payload.
  3. The RunCommandWindows extension is instantiated (auto-installed if missing).
  4. Script is executed as NT AUTHORITY\SYSTEM in a 64-bit PowerShell process.
  5. Output is returned to the portal/caller (last 4,096 bytes; requires outbound 443 connectivity).

Invocation Methods

# PowerShell — named built-in command Invoke-AzVMRunCommand -ResourceGroupName 'myRG' -VMName 'myVM' ` -CommandId 'RDPSettings' # PowerShell — custom script file Invoke-AzVMRunCommand -ResourceGroupName 'myRG' -VMName 'myVM' ` -CommandId 'RunPowerShellScript' -ScriptPath 'C:\scripts\Windows_Firewall_Rules_Validation.ps1' # Azure CLI — named built-in command az vm run-command invoke --resource-group myRG --name myVM \ --command-id RDPSettings # Azure CLI — custom script content az vm run-command invoke --resource-group myRG --name myVM \ --command-id RunPowerShellScript \ --scripts @Windows_Firewall_Rules_Validation.ps1 # Portal: VM → Operations → Run Command → select CommandId or RunPowerShellScript

Extension Log Location

C:\WindowsAzure\Logs\Plugins\Microsoft.CPlat.Core.RunCommandWindows\<version>\RunCommandExtension.log

🔧Troubleshooting Run Command Itself

Extension Stuck / Not Responding

Check log: C:\WindowsAzure\Logs\Plugins\Microsoft.CPlat.Core.RunCommandWindows\<version>\RunCommandExtension.log
Remove and auto-reinstall the extension:
Invoke-AzVMRunCommand -ResourceGroupName 'rgname' -VMName 'vmname' ` -CommandId 'RemoveRunCommandWindowsExtension'

Common Issues

Guest Agent NOT READY Check VM Properties in portal. Agent must be Ready. If not, check Azure VM Agent health first.
Output truncated 4,096 byte limit. Scripts should format output concisely; use table format (see Firewall Validation).
"Entity not found" error CommandId value is incorrect. Must exactly match a value from the official list.
Script runs but no output VM lacks outbound port 443 to Azure public IPs. Add NSG allow rule for AzureCloud service tag.
& symbol failure Escape with ^& in parameter strings passed to the script.
\n in file paths Replace \n with \N (e.g., C:\Windows\notepad.exe → use \N).
AutoRun registry key Check HKLM\SOFTWARE\Microsoft\Command Processor\AutoRun — can interfere with extension install.
Script times out 90-minute max. Break large scripts into smaller phases or use a custom script approach with output checkpoints.
